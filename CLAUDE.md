# Работа в этом репозитории

Личный проект, ревьюить некому: **коммитить и пушить прямо в `main`**. Ветки под задачу и
PR здесь не нужны.

## Сборка и установка

```sh
go install .          # обновляет ~/go/bin/yk-kai — то, чем пользуются агент и я
```

Перед коммитом: `gofmt -l .`, `go vet ./...`, `go test ./...`.

## Настройки, а не константы

Ни адреса инстанса, ни проекта, ни доски, ни логина в коде быть не должно: репозиторий
публичный. Всё это живёт в `~/.config/yk-kai/config.json` (`internal/config`) и
переопределяется переменными окружения. Примеры в коде, тестах и README — нейтральные
(`example.youtrack.cloud`, `PROJ-123`, `alice`).

Токен в argv не передаётся никогда: только `$YOUTRACK_TOKEN` или `sec get <token_ref>`.
Наружу отдаётся маска (`config.Mask`), не значение.

## Проверка правок на живом трекере

Тестового инстанса нет, поэтому проверять на своей задаче: создать проверочную, прогнать
на ней цикл (`create` → `link` → `comment` → `worklog` → `set`) и **удалить** её, чтобы не
копить мусор на доске:

```sh
curl -sS -X DELETE -H "Authorization: Bearer $YOUTRACK_TOKEN" \
  "$YOUTRACK_HOST/api/issues/<id>"
```

Команды `delete` в CLI нет и заводить её не надо: удаление задачи руками — исключение, а не
рабочий сценарий.

## Гочи API, на которых уже обжигались

- **Успешный ответ ≠ применённое изменение.** POST на `/api/issues/<id>` отвечает
  `{"id": ...}` и когда поле не записал. Поэтому `create` и `set` перечитывают задачу и
  дожимают непринятые поля (`ensureFields`), а не верят ответу.
- **Задача не попадает на доску сама.** После создания нужен POST в
  `/api/agiles/<agile>/sprints/<sprint>/issues`.
- **Отказ приезжает объектом, иногда с HTTP 200**: `{"error", "error_description"}`. Без
  проверки он разбирается в пустую структуру, и команда рапортует успех (`decode`).
- **Пробелы в query кодируются только как `%20`.** `url.Values.Encode` даёт `+`, YouTrack
  отвечает `invalid_query` на корректный запрос (`encodeQuery`).
- **`for: me` отдаёт не то** — логин подставляется явно из `/api/users/me`.
- **Free-text через `or` в скобках YouTrack не разбирает** и молча возвращает пустой список;
  `search` предупреждает.
- **У State собственный `$type`** — `StateIssueCustomField`. С `SingleEnumIssueCustomField`
  запрос проходит, а состояние не меняется.
- **`flag.Parse` останавливается на первом позиционном аргументе**, поэтому argv разбирается
  через `parseArgs`: иначе `search "project: PROJ" --limit 5` уезжает в YouTrack целиком.

## Скилл

Скиллов два, и они не синхронизируются автоматически:

- `skills/yk/SKILL.md` в этом репозитории — **обезличенная** копия для чужих: примеры
  `example.youtrack.cloud`, `PROJ-123`, `alice`, без правил конкретной команды. Ни адреса
  инстанса, ни проекта, ни логина здесь быть не должно;
- `~/.claude/skills/yk/SKILL.md` — мой рабочий, с реальными значениями и процессом. Он
  обычный каталог, не симлинк сюда и не под git.

Меняешь поведение команды или текст вывода — правь **оба**, иначе один из агентов будет
объяснять пользователю старое поведение.
