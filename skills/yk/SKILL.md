# YouTrack через yk-kai

Инструмент один — CLI **`yk-kai`** (`~/go/bin/yk-kai`). Самодельных обвязок над
`curl` не писать: то, что иначе требует ручного REST (привязка к доске, дожим
полей, разбор отказов), он делает сам.

**Гоча PATH:** `command not found: yk-kai` — обычно урезанный PATH, а не
отсутствие инструмента. Звать полным путём: `~/go/bin/yk-kai`.

**Инстанс, проект, доска и логин задаются настройками, а не кодом** —
`~/.config/yk-kai/config.json`. Посмотреть: `yk-kai config`. Разово
переопределить — переменными `YOUTRACK_HOST`, `YOUTRACK_PROJECT`,
`YOUTRACK_ASSIGNEE`, `YOUTRACK_AGILE_ID`, `YOUTRACK_SPRINT_ID`,
`YOUTRACK_TOKEN_REF`. Токен берётся из `$YOUTRACK_TOKEN` или из sec по
`token_ref` и в argv не попадает.

По умолчанию CLI печатает JSON-конверт (`v`, `command`, `exit`, `data`,
`warning`, `error`) — он для агента. `--human` даёт текст для человека: его и
показывать пользователю.

## Команды

```sh
yk-kai create "Summary" --type Bug --priority Major   # + цепляет к доске
cat desc.md | yk-kai create "Summary" --type Bug      # описание со stdin
yk-kai get PROJ-123 --full                            # + описание, связи, комментарии
yk-kai set PROJ-123 --state Review --assignee alice   # любые поля разом
yk-kai state PROJ-123 Done                            # сокращение для set --state
yk-kai comment PROJ-123 --file msg.md                 # или текстом, или со stdin
yk-kai board PROJ-123                                 # прицепить к доске отдельно
yk-kai search "project: PROJ #Unresolved for: alice" --limit 20
yk-kai link PROJ-123 "depends on" PROJ-456
yk-kai links PROJ-123
yk-kai worklog PROJ-123 2h "что делал"
yk-kai config                                         # где настройки и что в них
yk-kai doctor                                         # настройки, токен, пользователь, проект, доска
```

Коды выхода: `0` сделано и проверено, `1` YouTrack не применил (поле, доска,
связь), `2` ошибка инструмента или аргументов, `3` не найдено, `4` YouTrack не
ответил. Код `1` — это не «наверное получилось»: команда перечитала задачу и
увидела, что изменения нет.

## Значения полей

| Поле | Значения |
|------|----------|
| Priority | `Show-stopper`, `Critical`, `Major`, `Normal`, `Minor` |
| Type | `Bug`, `Cosmetics`, `Exception`, `Feature`, `Task`, `Usability Problem`, `Performance Problem`, `Epic` |
| State | `Backlog` → `To Do` → `In Progress` → `Review` → `Testing & Deploy` → `Done` → `Archived` |
| Assignee | логин пользователя |

Это набор по умолчанию; в проекте с другой схемой список правится в
`internal/youtrack/fields.go`. Значения понимаются и по-русски («Ошибка»,
«Обычная», «В работе») — CLI переводит их в английские сам. Незнакомое значение
отвергается **до** запроса, с перечислением допустимых, поэтому подбирать
написание вслепую не нужно.

## Правила

- Умолчания `create`: `Type: Task`, `Priority: Normal`, исполнитель из настроек,
  задача цепляется к доске. Тип и приоритет всё равно задавать осознанно —
  умолчание не повод оставить баг задачей.
- Описание и комментарий передавать **файлом или со stdin**, аргументом — только
  однострочники без кавычек и markdown.
- Назначенные задачи всегда запрашивать заново, не кэшировать.
- Ссылку на задачу в отчётах и описаниях MR давать отдельной строкой:
  `YouTrack: <host>/issue/PROJ-XXX`.
- Если в команде принято закрывать задачу после мержа — `yk-kai state PROJ-XXX
  Done` сразу, не спрашивая; зонтичным задачам вместо этого комментарий о
  прогрессе.

## Поиск

**Перечисление значений поля и перечисление слов — разный синтаксис, и второй
молча не работает.**

- Значения **одного поля** — через запятую, это OR:
  `State: {In Progress}, Review, {Testing & Deploy}`. Многословные значения — в
  фигурных скобках.
- Free-text слова через `or` в скобках **не разбираются**:
  `project: PROJ #Unresolved (пресет* or сесси*)` возвращает пустой список без
  ошибки. `yk-kai search` предупреждает об этом, но починить не может: несколько
  корней — отдельными запросами, результаты склеивать самому.
- **`for: me` отдаёт не то** — YouTrack считает «мной» не владельца токена.
  `yk-kai search` подставляет реальный логин сам и говорит об этом; в своих
  запросах сразу писать логин.
- **`#Unresolved`** — «не в терминальном состоянии», короче и надёжнее, чем
  перечислять `State: -Done, -Archived`. Хорошо комбинируется:
  `project: PROJ #Unresolved subtask of: PROJ-755`.
- **Free-text ищет по комментариям, а не только по summary и description.**
  Слово, мелькнувшее в обсуждении, вытащит чужую задачу. Для вопросов «что
  осталось по X» выдачу нельзя отдавать как есть: free-text'ом собрать
  кандидатов, потом отсеять по summary и описанию.

## Что CLI делает за тебя

Это грабли ручного REST — они закрыты, но знать о них надо, чтобы понимать вывод:

- **Задача не попадает на доску сама.** `create` кладёт её в спринт, `board`
  чинит забытое. Не прицепилось — команда вернёт код 1 и скажет, чем добить.
- **Успешный ответ ≠ применённое поле.** YouTrack отвечает `{"id": ...}` и на
  запрос, который ничего не записал (так задачи остаются без Assignee).
  `create` и `set` перечитывают задачу, дожимают непринятые поля и возвращают
  код 1 с перечислением того, что не встало.
- **Отказ приезжает объектом, иногда с HTTP 200** — `{"error", ...}`. CLI
  распознаёт это как ошибку, а не как пустой результат.
- **У State собственный `$type`.** С `SingleEnumIssueCustomField` запрос
  проходит, а состояние не меняется — поэтому состояние менять только `state` /
  `set --state`, не самодельным curl.
- **Связи ставятся командами** (`depends on`, `subtask of`, `parent for`,
  `relates to`, `duplicates`, `is required for`), а не эндпоинтом links с id
  типа связи и сторонами. После установки CLI перечитывает связи и проверяет,
  что связь появилась.
- **Стороны связи различаются по направлению**: у Subtask это `parent for`
  против `subtask of`. `links` и `get --full` печатают сторону этой задачи.
- **Время списывается полднем UTC.** YouTrack округляет метку до дня по UTC, и
  полночь по местному времени восточнее Гринвича уезжает на сутки назад.

## Когда что-то не работает

`yk-kai doctor --human` отвечает на вопрос «почему»: откуда прочитаны настройки,
какой токен подставился и откуда, кем видит нас YouTrack, доступен ли проект,
жива ли доска.

«Настройки не заполнены» — файла нет или в нём пустые `host` и `project`:
`yk-kai config init`, дальше заполнить.

Таймаут (код 4) — это латентность, а не «не сработало»: команды идемпотентны,
можно повторить. Перед повтором `create` всё же проверить поиском по summary,
иначе будет дубль.
